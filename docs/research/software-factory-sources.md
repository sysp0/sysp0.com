# Software factory source check (2026-11-07)

Primary sources only. These notes describe the cited implementations and the claims their authors made, not independently measured outcomes.

## Astro / Cloudflare triage

- [Cloudflare's account](https://blog.cloudflare.com/astro-issue-triage/) says Astro used isolated agents to **reproduce → diagnose → verify → fix**, passed findings in a `report.md`, published a `pkg.pr.new` preview for the reporter, and opened a PR after reporter confirmation. It describes a label-driven state machine, saying a new submission starts at “triage needed” and confirmation moves it to “fix verified.” Cloudflare reported open issues falling from over 200 to about 30 as of **August 4, 2026**; that is its own case study, not a general result.
- The [open-source Action README and state diagram](https://github.com/withastro/triagebot-action/blob/main/README.md) give the **exact configurable default labels**: `triage: needs triage`, `triage: not actionable`, `triage: needs reproduction`, `triage: skipped`, `triage: unable to reproduce`, `triage: unable to fix`, `triage: failed`, `triage: fix pending`, `triage: fix rejected`, `triage: fix verified`. An opened/reopened issue enters `needs triage`; that pipeline can exit to one of the seven outcome labels (`not actionable`, `needs reproduction`, `skipped`, `unable to reproduce`, `unable to fix`, `fix pending`, `failed`). From `fix pending`, reporter confirmation leads to `fix verified` and PR creation, while rejection leads to `fix rejected`. New actionable information can send `needs reproduction`, `unable to reproduce`, `unable to fix`, `failed` (at most three failed attempts), or `fix rejected` back to `needs triage`. `fix verified`, `not actionable`, and `skipped` are terminal in the README. One triage label is present per issue. **Caveat:** `auto-pr-on-fix: true` skips preview/confirmation and goes straight to `fix verified`; do not present the human confirmation step as universal.
- [withastro/triagebot-action](https://github.com/withastro/triagebot-action) is the reusable GitHub Action for issue triage. Its README says the agent runs shell commands on a standard GitHub Actions runner and uses project-specific triage skills. [withastro/flue](https://github.com/withastro/flue) is the open-source agent harness framework that the Action invokes; Cloudflare describes it as an open, platform-agnostic framework for durable agents/workflows. [Flue's own guide](https://flueframework.com/docs/guide/why-flue/) says it can run on Node.js, Cloudflare, GitHub Actions, and other hosts. **Do not link `github.com/cloudflare/flue`: it returns 404.** The Astro repository also has a separate [withastro/factory](https://github.com/withastro/factory) Worker implementation; avoid conflating its newer workflow with the GitHub Action.

## Vercel / eve and AI SDK

- [Vercel's workload-selection guide](https://vercel.com/i/first-software-factory-tasks) says investigation is a useful first workflow when a code change would be premature; choose work with a clear endpoint, reviewer-checkable evidence, constrained access, and a known stop condition. It expressly recommends choosing the workload **before** following its [eve software-factory implementation guide](https://vercel.com/kb/guide/eve-software-factory). [Vercel's general factory guide](https://vercel.com/docs/agent-resources/software-factory) explicitly warns that implementation before the problem is clarified can pass tests while solving the wrong problem.
- [Vercel's AI SDK factory report](https://vercel.com/blog/building-a-software-factory-for-ai-sdk) (Lars Grammel and Eric Dodds, **August 12, 2026**) says that after just over four production weeks, factory agents authored **25–35% of PRs merged each week to `main`**. Its introduction says the factory closed **70–80% of issues**, while the detailed results specify **over 75% of issues closed in July** were closed by the factory. These are shares of merged PRs and *closed* issues, respectively, **not** shares of all PRs or all open issues, and are Vercel's self-reported AI SDK results. Vercel says humans review and merge every change; the factory does not merge autonomously. Its reported open-issue backlog went from 1,022 in late June to 844 by early August.

## Limits and risks supported by the sources

- **Untrusted inputs and secrets:** [Vercel's AI SDK report](https://vercel.com/blog/building-a-software-factory-for-ai-sdk) treats public issues, PRs, comments, and links as attacker-controlled. It names malicious code/supply-chain changes, resource exhaustion, API-key exfiltration, and prompt exfiltration. Its implementation runs each agent in an isolated Vercel Sandbox with task-specific secrets, restricts network egress, and requires human approval to merge. These are Vercel's described controls, not guarantees for other factories.
- **Action-specific trust boundary:** the [Action README](https://github.com/withastro/triagebot-action/blob/main/README.md) requires separate read and write GitHub tokens and permits a GitHub App token or PAT for write access; it runs code on the GitHub Actions runner. A [public security issue in the Action repository](https://github.com/withastro/triagebot-action/issues/17) raises long-lived token and prompt-injection risks through issue bodies. It is an **open, third-party report**, not a maintainer-confirmed exploit or proof of compromise. The safer supported general claim is that an externally authored issue can carry instructions into an agent's context, so isolation, scoped credentials, and review matter.
- **Cost and throughput:** the [eve guide](https://vercel.com/kb/guide/eve-software-factory) says evals consume model tokens and the full pipeline pushes a real branch; run it deliberately. The [Vercel pilot guide](https://vercel.com/i/first-software-factory-tasks) asks for an exhausted-run-budget stop condition and a sample sized to review capacity, warning that a hundred unattended proposals are not useful if only ten can be reviewed. These sources support **budgeting and review-capacity limits**, but **no verified per-issue dollar cost, ROI, or universal throughput multiplier**.

## Definition / further reading

- [Matt Pocock's `dictionary-of-ai-coding` repository](https://github.com/mattpocock/dictionary-of-ai-coding) has a [Software factory entry](https://github.com/mattpocock/dictionary-of-ai-coding/blob/main/dictionary/Software%20factory.md): triggers such as issue creation, schedules, CI failures, or another session's completion start agent sessions; humans can remain at approval/review points. The repository URL is the stable link if a file path might be reorganized.
